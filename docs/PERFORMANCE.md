# 效能改善與驗證

使用 Windows／headless Edge、正式匯出的 Web 與隔離合成書架量測。
時間會受機器負載影響，回歸測試檢查資料量、DOM 數量與保存行為，不使用毫秒門檻。

| 場景 | 改善前 | 改善後 |
| --- | --- | --- |
| 1,000 列、每列僅 CV 欄有值的 XLSX | 100,000 個 td | 2,501 個 td，隨可見高度／overscan 改變 |
| 此工作表的筆記輸入到兩次 animation frame | 109–373 ms | 10–25 ms |
| 此工作表首次進入閱讀器 | 1.8–2.5 秒 | 約 0.73 秒 |
| 1 MiB 文字、主線 20 版，沙盒首次存一字修改 | 瀏覽器雜湊約 46 MiB | 約 3 MiB；重用原始檔與已驗證主線 |
| 同文件新增一字筆記的草稿請求 | 1,048,909 bytes | 321 bytes，不含全文 |
| XLSX 閱讀進度保存 | 重寫約 1.55 MiB manifest | 寫入約 162 bytes progress.json，不重寫 manifest |

表格只渲染可見列，單行儲存格可由 tooltip 查看完整值；列號定位能恢復畫面外的閱讀位置。
稀疏表格補出的空格也計入 `limits.sheetCells`，列高與預先渲染列數由設定控制。

VAX 驗證只重用同一個原始 Blob、相同且不可變的 metadata／節點物件。
節點、筆記、投影與文件指標均凍結；仍檢查順序、scope、重複 ID。
重新載入的資料重新驗證，變更原始檔／metadata 或篡改複製出的節點均拒絕。

IndexedDB v4 的原始檔／投影和版本節點分別保存，草稿只讀取 metadata，存版只追加新節點。
升級有內容的 v3 資料庫保留原始位元組、主線／沙盒事件、草稿、設定與進度。
升級交易失敗會回滾到 v3，之後能重試。

執行 `pnpm test:web` 包含流程與效能回歸測試；最新量測 JSON 在忽略的
`.preview/performance-tests/{run-id}/results.json`。

重新開啟仍完整下載與驗證主線歷史，尚未實作分頁載入。
正式版本與已修改全文的草稿仍完整保存，磁碟提交維持同步原子寫入。
