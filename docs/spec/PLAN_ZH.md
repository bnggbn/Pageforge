# 專案計劃

## 定位

Pageforge 是開源文件閱讀與管理工具，不以營利為主要目的。
後續定位延伸為 Local-First 的文件與思考沙盒：使用者可試寫、比較、採納或保留不同方向，
不必操作 Git CLI 或手動處理 merge conflict。完整提案見
[Local-First 跨平台思考沙盒架構](LOCAL_FIRST_ARCHITECTURE.md)。

- 個人：整理文件、閱讀、保存進度。
- 作者：管理作品、章節與版本。
- 社群：分享有權公開的文件、共同閱讀與交流。

## 原則

- 核心閱讀能力可在本機使用。
- 重視資料自主、匯出與備份。
- 原始內容與衍生內容分開保存。
- 雲端與 AI 功能需取得使用者同意後才傳送內容。
- 收費安排以維持營運與負擔成本為主。

## 開發順序

| 階段               | 範圍                                                                   | 完成條件                                         |
| ------------------ | ---------------------------------------------------------------------- | ------------------------------------------------ |
| 第一版             | Web 匯入、書架、閱讀、本機進度                                         | 通過 [MVP 驗收](MVP.md)                          |
| 作者管理與思考沙盒 | 文件更新、章節、版本、Fork／Adopt、可視化 Diff、靜默暫存、匯出         | 舊版本可找回，切換可恢復草稿，採納保留來源與歷史 |
| 社群分享           | 公開文件、分享連結、存取權限                                           | 公開與私人內容有明確邊界                         |
| 多端與託管         | Desktop、Mobile、Identity Bridge、選用物件儲存同步、自架、獨立操作軌跡 | 離線可用，衝突保留雙方，登入與文件授權明確       |
| AI                 | 摘要、分章、衍生版本                                                   | 保留原文，記錄來源與處理資訊                     |

各階段細節在開發前另寫規格，時程依投入與驗收結果調整。

## 後續架構候選

版本分支、Fork／Adopt、靜默暫存、內容定址儲存、Identity Bridge 與獨立會話事件鏈，
依 [架構提案](LOCAL_FIRST_ARCHITECTURE.md) 分階段細化與導入。
資料庫投影、離線授權與 AI 任務佇列仍待規格化。
導入前需定義寫入流程、失敗復原、並行修改、刪除與重建方式；
雲端同步為選用能力，不改變本機免登入的使用方式。

## 待確認

- 專案名稱已定為 Pageforge。
- MIT 授權範圍與著作權人。
- 作者管理與社群分享的優先順序。
- 託管預算、容量限制與維運方式。
